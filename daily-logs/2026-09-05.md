## Run 2 - Source-Constrained Pay Language Was Real But Fragmented

### Wake-up
The previous run proved that broad deliverable queries collapse into official and SEO noise. This run tested the corrected search behavior: source-constrained surfaces first, pay verbs second.

### Research
- Searched Insomnia, Facebook-visible group snippets and Freelancer.gr for "ψάχνω κάποιον", "θα πληρώσω", "να αναλάβει", "λίστα", and "πόσο".
- Freelancer.gr surfaced explicit deliverable demand, including an Excel list of Greek speech therapy, occupational therapy and psychotherapy centers, plus translation/product-description tasks.
- Facebook-visible snippets surfaced paid Greek-language practice time, pet-food forwarding, housing contract takeover, small travel/admin questions and errand-style help.
- Insomnia surfaced buyer/friction language but the strongest result was older customs/IOSS discussion, not a current paid helper lane.

### Ideas Considered
- `Therapy-Center Excel Lead List Desk` - 6.1 KILLED. Real paid deliverable, laptop-doable, but only one indexed same-object job and already inside Freelancer.gr acquisition. Needs repeated same-vertical list jobs or an actual bid/win to revive.
- `Paid Greek Practice Buddy Match` - 5.6 KILLED. Real pay language, but low-ticket, personal-trust-heavy and tutor/language-exchange adjacent.

### Learning
This run answers part of the user's concern: the engine was indeed over-starved by search method, not only strictness. Source-constraining brought pay language back. But the engine should not overcorrect into accepting every paid sentence. The new promotion gate is repeated same-job density in one reachable channel.
